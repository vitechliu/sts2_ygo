# VYgo 本地化

以 `VYgo/localization/zhs/` 为效果和文本结构的基准，仅向 `eng/`、`jpn/` 输出本次要求的翻译。处理所有实际存在的本地化表，不仅是 cards.json。用户只要求设计或维护本 skill 时，不执行全量翻译。

## 先确定范围

1. 读取项目 `AGENTS.md`，检查工作区变更。路径均相对项目根目录；不要改其他人正在修改的内容。
2. 枚举 `zhs/*.json` 与目标语言已有文件，统计新增、已有、缺失条目。全量任务覆盖中文全部 key；增量任务只改指定 key 及必要的同名引用。保留已有合格译文，发现过期或不一致才修订。
3. 将 JSON 按 UTF-8（兼容 BOM）解析为扁平字符串表。翻译值，不改 key、文件名、语言目录名、Model ID 或 CardId；沿用中文 key 顺序与目标文件已有缩进/BOM 风格，新文件使用 UTF-8。
4. 先读唯一术语表 [references/glossary.md](references/glossary.md)。新增或修改约定在此处维护；其余文档和脚本不要再内置一套术语替换表。

## 先建立名称映射

把名称与效果翻译分开处理。`cards.json` 的 `.title`、`monsters.json` 的 `.name`，以及描述、选择提示、事件、能力中的同名引用，共用一个按 CardId 索引的译名结果。

- 优先用 C# 类的实际 `CardId` 关联 `VYgo/db.json` 的 `card_id`，不要误用该 JSON 的数据库行号 `id`。卡与怪兽通过同一 CardId 关联，不能只依赖 key 字符串形似。
- key 与类名不一定严格可逆（例如 `SP` / `S_P`、旧生成器命名）；搜索实际类、注册和条目。缺少类时可以使用唯一的中文标题与 `cn_name` 精确匹配；中文去空格等归一化仅供查找候选，不作为最终身份依据。
- 同号多条、同名多卡、找不到身份时列入待核对，不能任选第一项。占位卡、测试卡、原创卡、衍生物应单独标注；保留中文表中仍被要求覆盖的历史条目，不自行清理。

### 英文名称

1. 首选对应 `db.json` 的非空 `en_name`，缺失时用 key 的名称部分生成；去掉类型前缀、字段后缀与怪兽 `_MINION`，将下划线或驼峰分词，保留缩写和数字。
2. 当前 Web 导入器会删除英文名的空格、标点，所以 `en_name` 可能是 `CyberDragon` 一类代码名。可做展示用分词，必要时结合 key 确认边界；不要声称这种结果已经核对过官方英文拼写，也不要为本地化修改 `db.json` 或 C# 标识符。
3. 项目允许直接使用数据名或 key 推导名。缩写、连写或标点无法可靠还原时，保留可解释的数据/key 推导结果并说明来源，不强制联网校对英文。

### 日文名称

1. 阅读 [references/name-sources.md](references/name-sources.md)，用已核实的真实卡号查询日文名称。优先百鸽 API 的 `text.jp_name`；有争议时以 Konami 日文官方卡片数据库为准，备用查询使用已核实的 `cid`。
2. 可使用 `scripts/fetch-japanese-names.py` 获取带来源、时间和官方页面链接的候选。脚本只查询和缓存，不会修改本地化；调用者仍须核对名称是否对应目标卡。
3. 日文名不能从中文、英文或 key 自行翻译。保留来源中的大小写、全角字符、中点及副标题；不要用 `jp_ruby` 的读音替换 `jp_name`，也不要把 HTML 注音带进游戏。
4. 项目衍生物的 CardId 可能由来源卡号加一生成，不能直接查该合成号码。查询召唤它的真实来源卡，从官方日文效果中的衍生物名称取得证据，或核实独立真实衍生物卡号。没有来源的原创名称应请求用户提供日文名或明确授权原创命名；真实卡名仍不得猜译。
5. 查询失败、字段缺失、身份冲突时，继续完成可确定的条目；未解决项保持原值或不新增，并在报告中列出，不用中文复制、英文名或猜译伪装成日文完成项。
6. 实际落地日文名称时，将采用的 `localization_keys`、`card_id`、`cid`（如有）、`jpn`、来源 URL/字段、查询日期及身份映射依据保存到 `VYgo/localization-name-sources.json`（在运行时语言目录之外）。已有记录按条目合并。衍生物记录来源卡号与含名称的短证据；不要复制整篇效果文本。

## 翻译其余文本

- 严格翻译本 Mod 中文效果的时点、对象、数值、次数、区域、升级差异和限制。外部游戏王资料只用于名称和术语，不把实体卡效果覆盖到 Mod 描述。
- YGO 术语依照集中术语表；原版 STS2 的状态、关键词和 UI 用语，从当前 `AGENTS.md` 所指游戏工程的 `localization/eng`、`localization/jpn` 按原版同一 key 查证。找不到时再给出明确的翻译决策，勿把游戏王区域名套到原版牌堆。
- `{Attack:diff()}`、`{Life}`、`{Amount}`、`{YgoName}` 等变量名称和格式调用保持不变。`show`、`cond`、`plural` 等格式器的条件、分支顺序与分隔符保持原义，但分支里的自然语言必须翻译，包括嵌套变量周围的文本。
- `[gold]`、`[blue]`、`[aqua]`、图标、资源路径等 BBCode 标记保持有效、配对和原有语义，随译文语序移动相应文本与标记。不要翻译标记名，也不要把 API HTML 直接嵌入 JSON。
- 区分 JSON 的 `\n` 换行与 `\\n` 字面反斜杠 n。遇到中文源的疑似错误先记录，不能在翻译过程中静默改变它的语义或扩大修改范围。
- Power `.description`、`.smartDescription` 和 Card `.description` 的格式化路径不同；需要查变量时分别检查代码与对应 CanonicalVars。不能将 Card 的变量规则直接用于 Power 普通说明。
- 英文使用自然、简短的游戏文本；日文使用自然的游戏说明语体。允许句式变化，不能省去条件或降低效果精度。

## 验证并交付

1. 解析全部改动 JSON，检查重复 key 和非字符串值（常规 JSON.parse/json.load 会吞掉重复 key，需使用能拒绝重复项的解析方式）。按本次范围核对缺失/多余 key、空译文，顺序与源表一致。
2. 对比变量名、格式器、嵌套分支和 BBCode。简单正则只能辅助查漏，不能用整段 `{...}` 必须相同的规则阻止分支文本翻译。中文与目标文本若共享原有格式问题，分别报告，不能宣称翻译新增。
3. 按 CardId 检查卡名、怪兽名及所有同名引用一致；核对每个已完成日文名称的来源记录。检查遗漏中文时，日文汉字不是中文残留的充分证据。
4. 修改译文后按项目要求在 `CHANGELOG.md` 最新版本下简洁记录实际覆盖范围，不新增版本号。只维护 skill 时说明是规范/工具准备，不宣称已完成游戏语言支持。
5. 仅改 skill 不需要构建游戏；改语言资源后如任务涉及资源打包，按项目发布流程验证。游戏内需要分别切换 eng/jpn 检查字体、换行、卡面、升级预览、悬浮提示与选择界面。静态检查或构建通过不等于 UI 验证完成。
6. 报告修改文件、各语言覆盖数量、名称来源、未解决条目与验证范围。全量请求存在缺项时明确标为部分完成；查询故障不构成编造日文名称的理由。
