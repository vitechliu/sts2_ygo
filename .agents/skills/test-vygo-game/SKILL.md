# VYgo 游戏测试

已跑通启动、主菜单截图、指定战斗、生成雷击、升级及两版本实际伤害验证。主菜单和牌面已观察；弃牌堆预览与完整 UI 回归尚未验证。具体数据和历史故障仅在需要证据或排错时读取 [references/verification.md](references/verification.md)。

## 测试存档约定

**本项目当前处于测试阶段，用户已明确授权：沿用当前存档；进入主菜单若有未完成对局，直接点 `ABANDON / 放弃` 并完成放弃流程，再开始测试，无需每次询问。不要为了保留旧对局切换存档，也不要寻找空闲存档槽。** 这一授权仅限 VYgo 当前测试流程，不适用于其他项目、任意存档删除或其他数据清理。用户后续明确要求保留某局时，遵循最新要求。

## 准备和启动

1. 读取当前 `AGENTS.md` 和 `git status --short`，不切分支、不覆盖无关改动。读取目标卡牌/配套随从和中文本地化，明确触发、目标、数值、升级及牌堆去向；UI 请求先明确目标组件与场景。
2. 游戏根目录从本机 `env.props` 的 `Sts2Dir`、AGENTS 或显式参数解析；原版/依赖源码从 `STS2_VANILLA_ROOT`、`RITSULIB_ROOT`、AGENTS 或参数解析，默认只读。技能、脚本和资源不写本机路径。
3. 新实现按项目规则 build/publish 后再启动；已有样例可核对安装 DLL 与对应构建产物哈希、安装清单、`release_info.json` 及实际加载日志。文件存在或进程启动不等于 Mod 已正确加载。纯技能文档修改无需构建游戏。
4. 使用当前官方 `computer-use` 技能，按它要求读取 guidance/api/confirmations。Windows 入口是持久 `node_repl` 中的 `import('@oai/sky')`；不要因 `cua_repl` native 禁用误判能力不可用，不自建 helper 协议。这里的项目放弃授权来自用户，不能被技能中的一般性确认建议替代。
5. `sky.list_apps()` / `list_windows()` 找现有游戏。未运行时核实安装目录的 `SlayTheSpire2.exe`，调用 `sky.launch_app({app: gameExe})`，再枚举。按返回的 app 路径和标题选唯一窗口，用真实 `id/app` 调用 `get_window`，随后 `get_window_state`；不要复用上次任务的句柄。
6. 启动时可能先返回黑屏；等待加载并重新观察，必要时核对游戏日志。确认主菜单和 VYgo 内容出现后再操作。

## 建立可控战斗

沿用当前存档，按上面的授权处理未完成对局。已验证的导航为：主菜单 `DUEL` → `自定义模式` → 选择测试角色 → 进阶 0、无额外特效 → 确认。按目标卡机制调整角色/前提；自定义模式仍可能保存对局或结算 Mod 进度，不能称为不落盘的沙盒。

新对局到达初始事件后，已可用控制台 `fight BOWLBUGS_WEAK` 直接进入双敌人战斗，不必先选事件奖励或走地图。该遭遇包含盛碗虫（石）及一个随机同伴；每次重新读取生命和能力，不能假定初始数值固定。来源为原版 `src/Core/Models/Encounters/BowlbugsWeak.cs`。

不要把 `TestMode.IsOn` 当普通游戏内测试开关：它会跳过控制台创建。`--bootstrap` 需要 `IBootstrapSettings` 实现，本项目此次未找到，不作为默认启动路径。

## 控制台与参数

每次输入前观察控制台编辑行与焦点；需要时点击输入行并刷新。用 `type_text` 输入文字，核对截图后在下一次调用用 `press_key` 发送 `Return`。不能把命令成功回执当作效果结算通过。

| 操作 | 已知用法与验证边界 |
| --- | --- |
| 开/关控制台 | **实测 `sky.press_key({window: targetWindow, key: 'Shift_L+8'})` 可双向切换。** `quoteleft` 被当前 sky 拒绝。战斗中 Escape 关闭控制台还可能弹出暂停菜单，优先用 Shift+8；若已暂停，观察后点“继续”。 |
| 清空输入 | `Control_L+u` 已实测，清除未提交文字。 |
| 生成 | `card <ModelId.Entry>` 默认加入手牌；已验证 `card V_YGO_CARD_RAIGEKI`。要求有效战斗与手牌空位。 |
| 升级 | `upgrade <hand-index>`，索引从最左侧 0 开始。每次生成/抽牌/打出后重数当前手牌，并核对回执的卡名。`upgrade 5` 仅是当次雷击位于第六张的记录。 |
| 指定战斗 | `fight <EncounterModel.Entry>`，已验证 `fight BOWLBUGS_WEAK`，要求对局已开始。 |
| 补全 | Tab 已调用；原版支持候选选择，Return 可能先接受候选。陌生模型查当前源码/注册日志并用实际回执确认，不批量猜 ID。 |
| 补能量/房间 | `energy <非负增加量>`、`room <RoomType>` 已查源码，尚未实测。只按具体测试需要使用。 |

`CardId` 是 YGO 数字 ID，不能用于代替控制台 `ModelId.Entry`。本地化 key 去掉 `.title` 可提供候选，最终看注册日志/控制台回执。原版签名来源：`src/Core/Nodes/Debug/NDevConsole.cs` 及 `src/Core/DevConsole/ConsoleCommands/` 下 `CardConsoleCmd`、`UpgradeCardConsoleCmd`、`FightConsoleCmd`、`EnergyConsoleCmd`、`RoomConsoleCmd`；版本变动或失败时才重新读取相关文件，不必每次重搜整套源码。

## 电子龙无限超量演出快捷测试

控制台执行 `vtest xyz-infinity`。`vtest`、`vtest help` 或 `help vtest` 查看帮助；`vtest ` 后按 Tab 可补全 `help` / `xyz-infinity`。

- 前提：构建安装后重启游戏，使用任意 VYgo 角色进入单机有效战斗，在玩家可行动阶段执行；关闭牌堆/选卡等弹窗，等待其他动作完成，随从区至少留一个空位。联机、回放、敌方回合、战斗结束中、场满等会返回中文错误。
- 指令自动关闭控制台，创建新的新星和无限来源战斗卡，先让新星登场，再只以该新星为已确定素材，按无限的正式规则执行超量素材预留、完整演出、无限登场和素材挂载。无需手动生成卡牌、支付能量或选择素材/额外目标，不消费场上原有怪兽。已有无限不会被复用；每次成功执行会新增一只无限，直到场满。
- 新星仅作为准备素材直接登场，不为它另做一次超量召唤，因此通常无限最终挂载一张新星素材。普通出牌/召唤 Hook 仍然生效，当前战斗能力可能阻止或影响测试；使用效果简单的测试局便于对照。
- 完整动画覆盖仅限本次异步执行上下文，成功/失败后恢复，不修改或保存用户的动画设置。失败不清空战斗、不强制回滚已发生的效果，已生成卡牌或已登场怪兽可能保留；先查看当前场面再重试。
- 执行完重新打开控制台查看 `[vtest]` 回执；异常详情写入游戏日志。应目视核对完整超量演出、无限登场、新星离场且成为无限的超量素材，并确认原有怪兽未被选作素材。回执中“完整演出调用已完成”只表示调用完成，不等于视觉效果已经验证。
- 验证边界：此指令已做编译、入口与资源静态检查，尚未游戏内实测。不要把这些检查记为实际召唤、画面、模式恢复或失败分支实测通过。用户未授权接管游戏时，仅交付指令由用户手测，不启动、操作或录制游戏。

## 卡牌结算断言

1. 在玩家行动阶段记录双方生命/格挡、能量、手牌/弃牌数及影响效果的能力。把目标源码与中文描述转成前后差值或状态断言，排除增伤、减伤、重放等干扰。
2. 生成目标卡，核对回执、手牌卡名、费用、牌面文字与卡图。需要升级时按当前索引升级并再次核对。
3. 依据最新截图选牌/拖牌到场地区域。**拖动后可能只是悬牌，未实际打出。** 若卡仍跟随鼠标且能量/生命/牌堆未变，不重复生成或判定失败；重看画面，将悬牌拖到更高的场地区域释放。不要用固定坐标宏。
4. 等过渡结束，再观察能量消耗、目标数值、卡牌离手/进入目标牌堆及其他预期状态。分别保存关键前后截图，记录预期和实际；复杂卡按其触发时机补足回合或素材条件。

可复用最小样例是 `Scripts/Cards/Category/Common/Raigeki.cs` 的雷击：1 费、全体 7 伤害，升级后全体 9。本次两版本均观察到正确伤害、能量和弃牌变化；数据见验证记录。更换卡牌时重新制定断言，不把雷击结论推广到召唤、联机或其他卡。

## UI 截图与收尾

- 先导航目标场景再检查稳定截图：主菜单从启动/返回获得，战斗组件沿上述流程进入；弃牌堆预览可在结算后点击当前弃牌堆入口再检查卡名、费用、动态值、贴图和裁切。**弃牌堆预览流程本次尚未执行，完整 UI 回归未通过。**
- 每个观察后只执行一个状态相关动作并刷新。游戏无障碍树可能仅显示通用窗口；主要依据画面定位，坐标动作传最新 screenshotId。用户输入、焦点变化、过渡或遮挡后重新观察；黑屏/残留/通知遮挡不能当稳定证据。
- 按官方技能处理窗口失效与有限重试；若再次出现 `SetIsBorderRequired ... 0x80004002`，才查验证记录中的兼容修复资料。已安装兼容层时不重复安装或验证探针。
- 实体 Escape 触发 computer-use 停止信号时，立即停止电脑操作并报告，不自动恢复。最后交代停留场景与当前测试局状态；不要为收尾切换存档。
- 交付卡牌/场景、前提、预期与实际、已保存截图的绝对路径、已验证与未覆盖项。发现 bug 保存最小复现，不擅自扩成玩法修复。截图先前观察过但未写入文件时明确注明，不能虚构证据文件。
