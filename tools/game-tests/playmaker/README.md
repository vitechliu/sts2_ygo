## 运行

1. 从项目根目录 `dotnet build`；资源有变化时执行项目发布。重启游戏加载最新 DLL。
2. 使用当前测试存档与藤木游作，自定义模式，进阶 0、无额外特效。进入有效单人战斗，在玩家行动阶段关闭所有选卡窗口。
3. `Shift+8` 打开控制台，执行 `vtest playmaker all`。单项复跑例如 `vtest playmaker cynetcrosswipe`；多项可用逗号连接键名。`vtest playmaker list` 列出键名，`status` 查询进度，`stop` 在当前动作结束后停止。
4. 每个用例会通过原版 `fight BOWLBUGS_WEAK` 重建测试战斗，清空本场战斗牌堆与能力，将敌人生命调整为 1000、玩家能量设为 30，准备 20 张抽牌堆卡。它会改变当前测试对局，不适合在需要保留的正式对局运行。
5. 报告逐项写入游戏 `user://vygo-tests/playmaker-时间.json`，控制台和游戏日志均输出绝对路径。Windows 默认在 `$env:APPDATA/SlayTheSpire2/vygo-tests`。

```powershell
./tools/game-tests/playmaker/summarize.ps1 -Reports @('报告路径1.json', '报告路径2.json') -OutputPath 'summary.json' -MarkdownPath 'summary.md'
```

## 结算覆盖

- 普通卡使用原版 `PlayCardAction` 检查可用性、目标、扣费与完整出牌生命周期。
- 连接召唤调用正式 `DirectExtraDeckSummonNetAction.Request`，经过目标身份同步、素材选择、合法性检查、消费、召唤和素材回调。准备素材的自动登场不计为目标卡通过。
- 怪兽行动通过 MinionLib `ExecuteCreatureActionGameAction` 执行；手发和能力调用公开右键入口并置于原版控制台动作上下文中。
- 使用原版 `CardSelectCmd.UseSelector(localOnly: true)` 自动选择候选，沿用 `PlayerChoiceContext`；不同选择入口的本地选择器同步细节不同，不能据此认定跨端同步通过。退出或异常后释放选择器。不启用 `TestMode.IsOn`，不修改卡牌实现。
- 回合条件通过真实 `EndPlayerTurnAction` 推进，等待玩家阶段与动作同步器均进入出牌阶段，避免将回合号提前递增误当作抽牌和回合开始效果完成；为避免随机敌人杀死测试对象，仅在回合测试时把敌人力量减低。
- 断言记录预期值、实际值、选卡候选、前后生命、攻击、能量和牌堆。基础/升级各建新战斗；工具衍生物只由电子界工具生成。
- 切换战斗和清场时等待卡牌消耗动画结束，防止旧战斗的延迟回收干扰下一用例。微码编码员分别验证普通弃牌不触发，以及手牌、场上连接素材生成电脑网魔陷。
- 任何断言失败即停止该版本，保留状态与异常，继续独立卡牌。动作超时或队列未清空时停止整批，不把仍在执行的动作当作已结束。
