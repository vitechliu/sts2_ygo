# VYgo UI 皮肤工作台

本工具将原版 UI 的切片和使用位置转换为可编辑目录，导出后由 VYgo 在组件实例上应用。首次交付没有绑定任何正式美术：开关默认开启，但没有映射的组件仍使用原版。

## 开始使用

在 `Web` 目录运行：

```sh
OPEN_BROWSER=false npm start
```

打开 `http://localhost:3000/ui-skin.html`，或点击后台顶部的 **UI 皮肤**。

1. 在“原版导出工程目录”填入包含 `images` 和 `scenes` 的本地目录，点击扫描。也可以设置环境变量 `STS2_VANILLA_ROOT`。目录只读，本机路径保存在不提交的 `local.json`。
2. 选择组件，再选择底图、阴影、描边等图层。原图已恢复透明留白，旁边显示原始画布尺寸。
3. 导入 PNG。独立图片可以直接使用；整张素材图集在画布上拖出裁剪区域。导入保留原始字节，按内容哈希保存，重复导入不会覆盖原文件。
4. 选择适配方式。九宫格模式下切换到“拖动九宫格边界”，拖动四条线；也可以输入精确像素值。四边依次为左、上、右、下。
5. 根据需要切换悬停、按下、禁用、选中及组合状态，为各状态指定素材。正常状态必填，状态图必须使用一致的输出尺寸、适配模式和九宫格边界。缺失状态依次回退组合状态的选中图、独立状态图、正常图。
6. 选择共用替换或指定场景。下方列表显示受影响位置。需要单独调整文字/点击范围时选择具体场景，再展开局部布局。
7. 保存映射，导出游戏皮肤。在 Godot 中重新导入生成的 PNG，运行项目 `publish.sh`，重启游戏。

如果目录没有目标组件：展开 **原版图片目录**，搜索原图，选择其场景使用位置，点击“为此位置建立映射”。动态创建的节点可以通过下面的游戏拾取流程补充。

目录包含“百科大全”“卡牌图鉴”“角色统计”分类，分别提供入口插图、按钮面板、图鉴侧栏背景、角色/类型/费用/稀有度筛选、排序按钮、统计页签、分享按钮及统计图标。其他 `scenes/screens` 和 `scenes/ui` 场景会自动收录到“其他界面”，所有 Atlas 均参与切片扫描；自动条目表示静态资源引用，未确认的动态状态仍需拾取或专用适配。

卡牌图鉴侧栏、角色统计行等原本使用 `ColorRect`，因此会显示为“纯色背景”。可像普通图层一样导入图片，支持九宫格和平铺；预览画布尺寸用于适配参考，游戏里仍沿用节点布局与点击范围。替换层位于原节点的文字/图标子节点后方，并按原始颜色校验，不改原控件的颜色属性。

统计图标按游戏时间、胜负、连胜等分别列出。它们由游戏动态创建，共用相同场景和节点路径，导出规则还会匹配各自原图，允许分别映射而不互相覆盖。卡牌图鉴的角色、类型、费用筛选与排序按钮已连接对应状态更新入口；排序按钮的“选中”表示降序，原版箭头翻转保留。

“原版组合 / 替换组合”用于比较图层位置，绿色框标出当前图层。它按场景锚点近似排版，不运行游戏脚本、容器布局或 Shader。严格像素、最终文字布局、阴影混合与动画仍需游戏截图验证。普通图层预览是导出的同一张图；九宫格和平铺预览则按所选尺寸生成。

## 比例、状态与布局

| 方式 | 行为 |
| --- | --- |
| 等比留白 | 按原版逻辑画布输出，保留素材比例，支持对齐和内容偏移 |
| 等比覆盖 | 填满原版画布并裁剪，使用对齐控制裁剪焦点 |
| 自由拉伸 | 输出到原版逻辑画布，允许改变长宽比 |
| 九宫格 | 导出裁剪和留白后的素材及四边参数，在游戏中随控件尺寸拉伸中部 |
| 平铺 | 导出原始重复单元，在游戏中随控件尺寸重复绘制 |

透明留白位于裁剪后的素材四周；九宫格边界以这个新画布为坐标。它们与文字内边距无关。原版 Atlas 的 Margin 也不是九宫格边界：`region.size + margin.size` 才是逻辑画布尺寸。例如确认按钮裁剪区为 257×132，加上留白后为 300×202。

默认保留原控件、输入、声音、缩放动画、焦点和可见性。只有启用“独立视觉层”时才隔离原版染色/Shader；此模式保留父节点变换和裁切，不改共享材质。正常模式仍使用原版染色，因此新图片可能被染成原按钮的悬停颜色。完整状态图建议逐状态检查是否需要隔离；仅换底图时通常不启用。

布局仅允许具体场景规则，节点路径相对于所选场景根节点。视觉区域和点击区域使用 Control 的四边锚点偏移值，不是 `x/y/width/height`。文字内边距目前针对 MarginContainer。容器托管节点可能被布局系统再次定位，需在游戏中验证；不存在的目标会在任何修改之前拒绝该规则。不会自动调整整页布局。

## 游戏内拾取

仅在启动游戏进程时明确设置 `VYGO_UI_INSPECTOR=1` 才安装开发拾取器，普通玩家不显示该入口。

- **F8**：进入/退出拾取模式。
- 悬停纹理控件：显示节点类型、尺寸、场景和匹配规则，青色框标出范围。
- **F9**：保存 JSON 到 Godot 用户目录下的 `VYgo/ui_skin_inspector/`，同时复制 JSON 到剪贴板。
- 在工作台点击 **导入拾取记录**，选择导出的 JSON，即可为此位置建立映射。

拾取模式屏蔽鼠标点击与滚轮，避免检查时触发按钮；退出后恢复正常输入。拾取按可见节点树顺序找最上层候选，复杂 CanvasLayer/ZIndex 叠放需核对记录的场景和节点。若节点已应用皮肤，导出仍记录原版纹理身份，而不是派生图路径。工作台导入后仍会检查原图能否从原版工程读取。

## 数据与接口

| 路径 | 用途 | 是否提交 |
| --- | --- | --- |
| `Web/ui-skin/local.json` | 原版工程本机路径 | 否 |
| `Web/ui-skin/catalog.json` | 自动生成的原版目录和指纹 | 否 |
| `Web/ui-skin/skin.json` | 编辑规则、素材适配参数 | 是 |
| `Web/ui-skin/sources/`、`sources.json` | 原始导入图片与名称索引 | 有实际素材后提交 |
| `Web/ui-skin/captures.json` | 自定义位置/拾取记录，刷新目录时重建 | 有实际记录后提交 |
| `VYgo/ui_skin/skin.json` | 运行时清单，schemaVersion=1 | 是 |
| `VYgo/ui_skin/generated/` | 内容寻址的派生 PNG | 有实际素材后提交 |

运行时清单仅包含资源身份、场景节点选择器、状态资源路径和适配参数，不包含编辑机绝对路径。导出先写入新图片，最后原子替换清单；导出失败不会损坏上一套皮肤。旧的派生图片不自动删除，确认不再引用后可自行清理。

API 前缀为 `/api/ui-skin`：

| 方法与路径 | 输入 / 输出 |
| --- | --- |
| POST `/scan` | `{root?}` → 原版目录 |
| GET `/catalog` | 当前目录 |
| GET / PUT `/config` | `{schemaVersion:1,rules:[...]}` 编辑配置 |
| POST `/sources?name=...` | `image/png` 原始请求体，最大 20 MB → 素材 ID、尺寸 |
| GET `/sources`、`/sources/:id` | 素材清单、原始 PNG |
| GET `/original?id=...` | 恢复透明留白后的原版 PNG |
| POST `/preview` | `{rule,state,size?}` → PNG |
| POST `/capture` | 拾取记录 → 更新后的目录 |
| POST `/export` | 已保存配置 → 规则数、图片数、指纹 |

编辑规则的最小示例（素材 ID 从导入返回值取得）：

```json
{
  "id": "confirm-image",
  "componentId": "confirm",
  "slotId": "Image|texture",
  "scope": "component",
  "states": {
    "normal": {
      "source": "<导入返回的哈希>.png",
      "crop": [0, 0, 180, 90],
      "padding": [0, 0, 0, 0],
      "mode": "nine",
      "border": [16, 16, 16, 16]
    }
  }
}
```

组件共用与局部规则可以同时存在，局部规则优先。同优先级的重复节点映射、冲突布局、越界切片、重叠九宫格和不一致状态尺寸会阻止保存或导出。导出会重新检查原版指纹，文件变化后必须刷新目录、核对并重新保存。

预置组件包括确认、返回、继续、弹窗、悬浮提示、滚动条、下拉菜单、复选框、页签和音量滑块。状态桥接覆盖 NClickableControl、NTickbox、NSettingsTab、NScrollbar、NDropdownScrollbar；其他原版或第三方脚本若自行在运行中重新赋值纹理，需要补充对应状态入口。静态 Theme 中的纹理需通过节点本地覆盖或拾取记录指定，不修改全局 Theme。

## 验证

```sh
cd Web
npm test
```

项目根目录执行 `python3 tools/ui-skin-tests/run.py` 可在临时 Godot 工程中测试当前生产源码，包括 Atlas 身份、实例应用、动态节点、状态回退、局部规则优先、StyleBox 隔离、独立视觉层、节点释放和关闭开关。脚本从 `env.props` 解析本机依赖，不写游戏存档或正式皮肤配置。

构建：`dotnet build`。资源发布：`./publish.sh`。游戏验收还需覆盖三种语言、长文本、鼠标/手柄、不同窗口比例和两个外观开关的四种组合。节点测试与浏览器预览不能代替完整游戏截图验证。
